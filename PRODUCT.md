# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Partner consultants who advise customers on GitHub Copilot rollouts. They have
never downloaded or analysed the Copilot usage metrics NDJSON reports, and
anyone else who wants to learn the data. A presenter can use the page to
explain the data while sharing a laptop screen. Readers can also use it alone.

## Product Purpose

A single local, static reference page that explains the GitHub Copilot usage
metrics NDJSON reports: what report types exist and how they relate, which
fields matter, how to get the files (dashboard and REST API, with
permissions), how to use them, and what their limits are. Success: a partner
consultant can name the right report for a question, read a record, and avoid
the common misreadings.

## Positioning

A visual, source-cited map of the reports and an annotated synthetic record,
in plain language. It is not a dashboard, not a measurement method, and not a
replacement for GitHub Docs.

## Operating Context

Opened from disk or a local server. Shown on a shared laptop screen, or read
alone. No network calls. No login.

## Capabilities and Constraints

- Static HTML, CSS, and JavaScript. No build step, no external requests.
- Every important statement links to public GitHub Docs (Enterprise Cloud).
- Sample data is synthetic and based on the public example schema.
- No internal GitHub data, no customer or partner names, no non-public product
  information.
- Must not present usage, adoption, or modeled savings as proof of business
  value or causation.

## Brand Commitments

- Light theme. Use the full width of a laptop screen.
- Plain, simple language in ASD-STE100 style. No jargon where a plain word
  works. No em dashes.

## Evidence on Hand

- Public GitHub Docs pages on Copilot usage metrics (cited on the page).
- No real export files. Do not invent results, prices, benchmarks, or
  customers.

## Product Principles

1. Cite the source next to the claim.
2. Show the data, then explain it.
3. Name the limits as clearly as the uses.
4. Keep it safe to share publicly.

## Accessibility & Inclusion

Readable at screen-share zoom levels. Keyboard reachable controls. Respect
reduced motion.
